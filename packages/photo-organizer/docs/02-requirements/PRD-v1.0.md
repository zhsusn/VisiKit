## 1. 产品定位

**一句话描述：** 本地离线运行的照片时间轴归档与去重工具，支持用户手动指定人物/景物分类，结合EXIF时间元数据自动建立`/内容类型/年份/`层级目录，解决长期备份积累的照片混乱与冗余问题。

**核心价值主张：** 
- **零风险整理：** 只移动不删除，源文件保留可回滚
- **零隐私泄露：** 完全本地运行，无需联网上传，**第一版不启用任何AI视觉模型**
- **零学习成本：** 一键式自动化处理，分类策略由用户预设或基于目录名自动映射
- **可扩展架构：** 目录结构`/人物/2023/`为未来AI自动分类预留标准，第一版通过手动参数指定实现

## 2. 用户故事

&gt; 作为一个**摄影爱好者/家庭用户**，我十多年来在不同设备备份了大量照片，为了防止丢失养成了"宁可重复存多次"的习惯。现在硬盘里有数万张照片，占用大量存储空间，且散落在几十个文件夹中。我希望有一个工具能够**安全地**帮我：
&gt; 1. **按拍摄年份**把照片整理到清晰的目录结构（如`2023/`、`2024/`）
&gt; 2. 区分**人物照**和**风景照**存放到不同根目录（我可以预先手动区分，或告诉工具当前批次是什么类型）
&gt; 3. 识别出哪些照片是**重复的**（即使文件名不同），并隔离到待确认目录
&gt; 4. **绝对不能误删任何一张照片**，所有操作必须可撤销
&gt; 
&gt; **第一版期望：** 我不需要工具自动识别照片内容（暂时不需要AI），但我希望目录结构能支持`/人物/2023/`这种层级，方便我后期手动整理或未来接入AI。

## 3. 功能列表

### P0（Must Have）- 核心功能

#### P0.1 时间轴智能归档（支持内容分类目录结构）
- **功能描述：** 解析照片EXIF元数据中的拍摄时间（DateTimeOriginal），根据用户指定的内容类型（人物/景物/未分类），自动创建`{类型}/YYYY/`或`{类型}/YYYY/YYYY-MM/`层级目录。第一版通过命令行参数`--category-type`（可选值：`person`、`scenery`、`unsorted`）手动指定分类，而非AI识别。
  
- **验收标准（AC）：**
  1. **时间解析准确性：** 成功解析EXIF时间的照片比例≥95%，解析失败时降级使用文件修改时间并标记`[估计]`
  2. **目录结构严格遵循：** 当`--category-type=person`时，照片必须归档到`/人物/2023/`（或`/人物/2023/2023-05/`二级模式）；`scenery`对应`/景物/2023/`；未指定时默认`/未分类/2023/`
  3. **冲突处理：** 同一目标目录下同名文件自动重命名（添加`_序号`后缀），绝不覆盖现有文件
  4. **跨区移动安全：** 跨磁盘分区移动时采用"复制+校验+标记删除"事务，确保源文件在写入确认前不被移除
  
- **技术风险提示：** 
  - ⚠️ **EXIF格式兼容性：** 不同相机厂商（佳能、尼康、索尼、手机）EXIF字段命名差异，需依赖`exifread`或`Pillow`库充分测试；HEIC格式需额外解码器
  - ⚠️ **时区处理：** 部分设备存储UTC时间，部分存储本地时间，需统一转换为本地时区避免跨年错误

#### P0.2 重复检测与隔离
- **功能描述：** 基于双重哈希算法（文件MD5精确匹配 + 感知哈希pHash模糊匹配）检测重复或相似照片。对于重复组，保留质量最高（文件大小最大或分辨率最高）的版本作为主文件，按正常规则归档到`/去重后照片/`；将组内其他重复项移动到`/重复照片/`目录，保留原有目录结构，等待人工二次确认后可直接删除。
  
- **输出目录结构：**
  ```
  {输出目录}/
  ├── 去重后照片/
  │   └── {类型}/YYYY/照片文件（保留的重复组主文件）
  └── 重复照片/
      └── {原始相对目录结构}/重复照片文件（重复组中的其他文件）
  ```
  
- **处理逻辑：**
  1. 重复组中质量最高的文件 → `/去重后照片/`（按时间/识别规则归档）
  2. 重复组中其他文件 → `/重复照片/`（保留原目录结构）
  3. 用户确认后可安全删除`/重复照片/`目录以释放空间
  
- **验收标准（AC）：**
  1. **精确重复检出：** 100%二进制相同的文件（MD5一致）检出率100%，无误报，处理速度&gt;500张/分钟
  2. **相似重复检出：** 同一照片的不同压缩版本、轻微编辑版本（亮度调整、裁剪&lt;10%）相似度≥95%时检出率≥80%
  3. **智能分离：** 重复组中保留质量最高的1个文件按正常规则归档到`/去重后照片/`，其余文件保留原目录结构移入`/重复照片/`
  4. **安全隔离：** `/重复照片/`目录保留完整原始目录结构，便于用户确认后直接删除释放空间
  
- **技术风险提示：**
  - ⚠️ **计算资源消耗：** 大文件（如单反RAW格式&gt;20MB）的MD5计算和pHash计算可能阻塞主线程，需异步多线程处理
  - ⚠️ **误判风险：** 连拍照片（内容高度相似但不同帧）可能被误判为重复，需增加"连拍模式检测"（1分钟内同一设备的相似照片视为连拍，保留全部）

#### P0.3 安全移动机制（防误删核心）
- **功能描述：** 采用"移动而非删除"的保守策略，所有整理操作实际为**复制+延迟删除**（软删除）。建立操作日志数据库，支持操作的原子性回滚。提供"演练模式"（Dry Run），预览所有即将发生的移动而不实际执行。
  
- **验收标准（AC）：**
  1. **零删除承诺：** 任何代码路径不得包含`os.remove()`或`shutil.rmtree()`，仅允许`shutil.copy2()`+延迟标记删除；软删除保留在系统回收站或隐藏`.trash`目录
  2. **原子性保证：** 每批次操作前自动创建 SQLite 快照，异常中断后可基于`--resume`参数恢复至上一致状态，或基于`--rollback`完全撤销本次会话操作
  3. **演练模式：** 使用`--dry-run`参数时，生成完整操作清单（CSV格式）但不实际移动文件，清单包含：源路径、目标路径、操作类型（移动/复制）、重复判定依据
  
- **技术风险提示：**
  - ⚠️ **磁盘空间双倍占用：** 移动操作实际为先复制后删除源文件（软删除），处理期间需要2倍于照片体积的磁盘空间，需在启动前预检磁盘空间
  - ⚠️ **跨分区原子性：** Windows系统C盘到D盘的移动非原子操作，中断可能导致重复文件，需通过事务日志确保可回滚

#### P0.4 审计日志与整理明细记录
- **功能描述：** 记录所有自动化决策（时间戳解析来源、去重判定依据、分类类型）和系统异常（文件占用、权限拒绝、EXIF解析失败）。整理完成后生成 `整理明细.md` 文件，记录每张照片的整理前后路径映射，便于追溯和回滚。
  
- **整理明细文件格式：**
  ```markdown
  # 照片整理明细
  **整理时间：** 2026-03-22 14:30:00
  **源目录：** D:\备份\手机照片
  **输出目录：** D:\照片整理_20260322
  
  | 序号 | 整理前路径 | 整理后路径 | 操作类型 |
  |------|-----------|-----------|---------|
  | 1 | D:\备份\手机照片\IMG_001.jpg | D:\照片整理_20260322\去重后照片\人物\2024\IMG_001.jpg | 归档 |
  | 2 | D:\备份\手机照片\重复\IMG_001_copy.jpg | D:\照片整理_20260322\重复照片\重复\IMG_001_copy.jpg | 隔离重复 |
  ```
  
- **文件位置：** `整理明细.md` 保存在输出目录根目录下，与整理后的照片目录同级。
  
- **验收标准（AC）：**
  1. **完整性：** 每条记录包含：时间戳、源文件路径、目标文件路径、操作类型（归档/去重隔离）、分类类型（人物/景物/未分类）、时间解析来源（EXIF Original/EXIF Digitized/文件修改时间）、异常堆栈（如有）
  2. **整理明细文件：** 每次整理完成后自动生成 `整理明细.md`，包含整理时间、源目录、输出目录，以及完整的文件路径映射表格
  3. **分级存储：** INFO级别记录成功操作，WARN记录降级处理（如使用文件修改时间替代EXIF），ERROR记录失败详情（含异常堆栈和文件路径）
  4. **可查询：** 提供`--report`命令行参数，可基于日志生成整理摘要（处理总数、分类分布、释放空间预估、失败文件清单）
  5. **日志轮转：** 日志文件按日期分割，单文件不超过100MB，防止长期运行占用磁盘
  
- **技术风险提示：**
  - ⚠️ **I/O性能：** 高频小文件写入（每张照片一条日志）可能拖慢处理速度，需采用内存缓冲+批量写入策略（每100条刷盘一次）

#### P0.5 EXIF元数据修复与校验
- **功能描述：** 修复损坏或缺失的时间戳元数据。对于缺失拍摄时间的照片（如截图、网络下载图片），基于文件创建时间推断并写入EXIF（可选），或在文件名中标记`[无EXIF]`。检测并报告时间异常（如1970年或未来日期）。
  
- **验收标准（AC）：**
  1. **异常时间检测：** 识别出时间戳在1970-1980年（Unix时间戳错误）或超过当前日期+1天的异常照片，单独移动到`/{类型}/时间异常/`目录
  2. **时间修复策略：** 提供`--fix-time`参数，允许将文件修改时间写入EXIF的DateTimeOriginal字段（需谨慎确认），或仅标记不修改
  3. **元数据保留：** 归档后的照片必须完整保留原始EXIF信息（包括GPS、相机型号、镜头信息），不得因复制操作丢失元数据
  
- **技术风险提示：**
  - ⚠️ **写入风险：** 修改EXIF属于写操作，与"只移动不修改"的安全原则冲突，必须作为可选功能（默认关闭），且仅在`--fix-time`显式开启时执行

## 4. 非功能需求

### 4.1 性能需求（基于纯Python桌面应用）

| 指标 | 目标值 | 测试条件 |
|------|--------|----------|
| **单张照片处理延迟** | &lt; 200ms | 仅EXIF解析+哈希计算（无AI推理），图片大小&lt;10MB |
| **批量处理吞吐量** | &gt; 300张/分钟 | 4线程并发，硬件为普通笔记本（i5-12代，16GB内存） |
| **内存占用峰值** | &lt; 1GB | 处理10万张照片批次时不触发系统swap（第一版无AI模型） |
| **启动时间** | &lt; 1s | 无需加载AI模型，仅初始化日志和数据库 |
| **磁盘I/O** | 顺序读写优先 | 避免随机小文件写入，日志批量刷盘，支持SSD/HDD |

### 4.2 安全需求（基于本地单机应用）

- **数据隐私：** 所有处理必须在本地完成，**严禁调用云端视觉识别API**（第一版无AI，第二版仅使用本地模型权重）
- **权限最小化：** 仅需文件系统读取/写入权限，不申请网络权限（防火墙可完全阻断）
- **数据完整性：** 所有文件操作采用"先复制后验证（MD5校验）再标记删除"策略，确保比特级完整性
- **防误删：** 提供`.trash`软删除目录（保留7天自动清理）和`--rollback`全量回滚能力

### 4.3 兼容性需求

- **操作系统：** Windows 10/11（64位）为主力支持平台，兼容Windows 7（Python 3.8+）
- **文件系统：** 支持NTFS（Windows）、exFAT（移动硬盘），支持中文/日文/韩文长路径（&gt;260字符需启用Windows长路径支持）
- **图片格式：** 必支持JPG、PNG、HEIC（iPhone）、RAW（佳能CR2、索尼ARW，仅提取预览图处理）、BMP、GIF
- **编码支持：** 文件路径和EXIF元数据支持UTF-8编码，兼容GBK编码的老照片（Windows中文环境遗留）

## 5. 业务异常及预期行为

| 异常场景 | 检测时机 | 预期行为 | 日志级别 |
|----------|----------|----------|----------|
| **EXIF数据损坏或缺失** | 解析阶段 | 使用文件修改时间替代，文件名添加`[估计]`前缀，继续处理；若`--strict`模式则跳过 | WARN |
| **文件被其他程序占用** | 移动阶段 | 跳过该文件，记录路径，继续处理其他照片，最后生成"被占用文件清单.txt" | ERROR |
| **磁盘空间不足（&lt;5GB或&lt;待处理体积×2）** | 启动前预检 | 拒绝启动整理流程，提示用户释放空间，推荐启用`--dry-run`模式预演 | ERROR |
| **目标目录已存在同名文件** | 移动前检查 | 自动重命名（添加`_序号`后缀），绝不覆盖，记录映射关系到数据库 | INFO |
| **时间戳异常（1970年或未来日期）** | 解析阶段 | 移动到`/{类型}/时间异常/`目录，记录原始值和推断值，等待人工确认 | WARN |
| **照片格式不支持（如WebP新格式）** | 解码阶段 | 跳过处理，移动到`/{类型}/不支持的格式/`目录，记录文件路径 | WARN |
| **权限拒绝（无写入权限）** | 移动阶段 | 尝试以管理员权限重试一次，仍失败则跳过并记录，继续处理 | ERROR |
| **源路径与目标路径在同一分区** | 移动策略选择 | 使用`os.rename()`原子移动，避免复制+删除的双倍空间占用 | INFO |
| **重复检测哈希碰撞** | 去重阶段 | MD5碰撞概率极低，但pHash相似度90%以上时增加文件大小二次校验 | WARN |

## 7. 附录

### 7.1 第一版使用示例（命令行）

```bash
# 场景1：整理人物照片（手动指定分类）
python photo_organizer.py --input "D:\备份\手机照片\人物" --output "D:\整理" --category-type person --structure year

# 结果：D:\整理\人物\2023\IMG_001.jpg
